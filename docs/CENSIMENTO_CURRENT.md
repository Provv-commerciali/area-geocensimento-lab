# Known current Censimento behavior

Navigation: Censimento → Nuovo Contatto, Contatti, Zone (Elenco/Nuova), Complessi.

A zone is created through cascading country, region, province/unità territoriale and municipality selections loaded from persistent Supabase reference tables, then name and assignee. The Italian hierarchy is synchronized separately from the official ISTAT/SITUAS archive; the 2026-02-21 snapshot contains 20 Regions, 110 intermediate units and 7,894 active Municipalities. Existing municipality streets can be associated and new streets can be created explicitly. Streets belong to zones through a many-to-many relationship. Civics are managed from a zone street as a single value, an inclusive range (all/even/odd) or a manual list; number and extension remain separate and normalized duplicates are rejected.

The primary operational concept and navigation entry is the Census Contact. A contact may be a private person or a company and remains attached to its zone/street/civic context, optional complex, property data and interview history. Its sheet exposes “Modifica contatto”, which updates the primary Subject identity, relationship role and property/context fields atomically without creating an interview; the same editor retains the Civic map picker so coordinates can be added or corrected. “Elimina contatto” requires explicit confirmation and removes only the selected CensusRecord context and its dependent history, never the shared Subject registry entry. Internally, a normalized Subject registry supports reuse across contacts without becoming an autonomous management area. Subjects and records are many-to-many with Proprietario, Comproprietario or Inquilino roles. During Nuovo contatto the operator can select an existing registry entry; matching CF/P.IVA prompts reuse, while names never merge automatically. Contact types confirmed are Generico, Informatore, Informazione and Notizia. Appraisal is manual and defaults false even for Notizia.

Interviews remain historical children of one Census Contact/context. Creating a CensusRecord never creates an interview or synthetic event. The contact sheet exposes other contexts linked to the same internal registry entry without sharing interview rows. “Non ancora contattati” remains derived from zero real interview rows on the context.

The Contact list now derives days since the latest real interview and one primary operational state. Precedence is overdue recall, stale Notizia, never contacted, then ordinary. A later interview fulfils an earlier recall; a Notizia becomes stale only after its interview age strictly exceeds the persistent `stale_news_days` threshold. Accessible text-and-icon badges use one visual configuration shared with the domain projection. Filters for Mai contattati, Ricontatti scaduti, Notizie non aggiornate and their combined Attività da fare run over the same records loaded by the active repository, including real Supabase data. The minimal Impostazioni operative screen is reached from Contatti and does not change the approved main navigation.

GeoCensimento presents its filters horizontally above a full-width map, filters the same real records locally and clears Via whenever Zona changes. Civics with persisted verified or automatic coordinates become markers; matching unlocated records remain visible in the counters and the first matching address centers the view through a non-persisting lookup. PostGIS point reads accept the GeoJSON, WKT or EWKB representations returned by the persistence boundary. The official orange `fabbricati` overlay is loaded as one EPSG:4258 WMS image per map view. Parcel point information resolves Province and Comune by matching the cadastral municipality code returned by AdE against persisted Municipality data—never by taking the first loaded zone—and presents the identifiers in a structured card. Provider failure text states which cartographic layer is unavailable instead of exposing an internal “errore gestito” label.

Civic number and extension are separate. `Intero edificio` stores the number of levels; `Parte di edificio` stores a controlled floor code, optional total floors and an independent top-floor flag. Qualification is controlled to Proprietario/Comproprietario/Inquilino; occupancy uses the five confirmed values. A complex has a zone, name, sheet/parcel and description and may link to many civics/extensions. The contact form only offers complexes already associated with its selected civic and never creates territory implicitly.

Complex detail also manages private Complex and Doorbell photos. Doorbell analysis is explicit and produces only review proposals. The mass grid supports correction, Privato/Azienda, canonical Civico/Piano/Qualifica/Occupazione, optional Scala/Interno, weak-match review, session duplicate warnings, merge/split and manual entry when OCR is unavailable. Final confirmation creates normal Contacts with zero interviews, hence Mai contattati.

The Contact list retains “Apri” and also offers “Modifica”, which opens the canonical editor directly. Contact detail has one enriched “Dati catastali” section. After a free confirmed parcel association, an authorized operator can explicitly request property units, select one subaltern, request its holders, associate a strong CF/P.IVA match, open the normal prefilled Nuovo Contatto flow, or request an ordinary report. Catasto-derived contacts still use `create_census_record_lab` with `p_interview = null`, so they are Mai contattati. Original right and share strings are retained even when they cannot be truthfully mapped to the smaller Censimento qualification vocabulary.
